## 2. 토스 사용자 인증으로 키를 실제 사용자에 묶기 — 취약점 점검 2026-10-20
- **왜**: AI·백업 키는 앱이 만들어 보내는 값이라 서버가 진짜인지 모른다. 공개 키·Origin 은 브라우저 밖에서 흉내 낼 수 있어, 가짜 키로 키당 상한(AI 하루 100회)을 우회하고 광고 없이 AI 를 직접 부를 수 있다. 지금은 임시 완화로 AI 전체 하루 3,000회·백업 표 300MB 상한(`contract/CHANGELOG.md` 2026-10-20 [server]).
- **방법**: 사용자 식별키 인증 코드 교환(SDK 3.6.0 이상, 300초 1회용 코드, 서버는 mTLS 인증서로 토스 API 호출) → Edge Function 이 진짜 토스 사용자일 때만 AI·백업을 허용. 키당 상한이 진짜가 되어 전체 상한을 다시 올릴 수 있다.
- **필요한 것**: SDK 3.2.0 → 3.6.0+ 업그레이드와 회귀 시험, 콘솔 mTLS 인증서 발급(사용자 — 콘솔 MCP 에 없음), 인증서를 Supabase secrets 로(사용자), 서버 코드·처리방침 검토
- **크기**: 큼 — 2.1.0 후보

## 3. (제안) 광고 보기 전에 AI 서버 여유 확인
- 전체 상한(하루 3,000회)에 닿은 날은 광고를 본 뒤 `limited` 가 나와 광고만 보고 AI 를 못 쓴다. 광고 전에 오늘 여유만 묻는 가벼운 확인(목표·키 없이)을 두면 막을 수 있다. 실제 사용량이 상한에 가까워질 때 의미가 있어, 13단계 운영에서 매주 `ai_draft_cost` 를 보고 정한다.

## 4. 칸을 하나라도 채운 뒤에도 AI 를 쓰게 하기 — 사용자 제기 2026-10-21 (대안 검토 중)
- **지금(2.0.0)**: 홈 'AI로 초안 만들기'는 세부 목표·실천이 하나도 없을 때만 보인다(`HomeScreen.tsx` `offerAi`). 하나라도 채우면 사라지고, AI 는 '편집' 화면 아래 버튼(가운데 = 빈 세부 목표, 둘레 = 그 세부 목표의 빈 실천)에만 남아 홈·세부 목표 화면에서는 안 보인다. 초안 흐름(`useAiDraft.runDraft`)은 이미 지금 판을 바탕으로 빈 칸만 채우고 적은 칸은 그대로 둔다 — 막힌 건 홈 버튼 조건뿐.
- **대안**: ① 홈 버튼을 빈 칸이 남아 있는 동안 유지('AI로 빈 칸 채우기 n칸', 같은 초안 화면·미리보기, 광고 1회로 판 전체) ② 트리 단계별 버튼(홈 = 빈 세부 목표, 세부 목표 화면 = 그 가지의 빈 실천 — 편집 화면 버튼을 보이는 곳으로) ③ 칸 입력 시트 안 'AI 추천' 후보 고르기(광고 1회로 그 블록 후보, 큼) ④ AI 가 쓴 칸만 다시 쓰기(보조, `aiDraft.cells`) ⑤ 사용자 칸 덮어쓰기(비추천).
- **추천**: ① + ② (작고 안전, 기존 기능을 보이게만). 진입점이 늘면 AI 사용량이 늘어 서버 하루 상한(3,000)·'광고 전 여유 확인'(3번)을 같이 본다.
- **결과(2.1)**: 사용자가 ① + ② 로 정해 넣음. 같은 버전에서 편집 화면을 없애(그 자리 편집 모드) 가운데 블록 채우기(빈 세부 목표만)는 빠지고 ①(홈 'AI로 빈 칸 채우기')이 맡음. 같은 날 ①도 초안 화면을 거치지 않고 바로 광고 → 그 자리 채우기로 바꿈(사용자 '뎁스가 깊어지는 게 싫어').
