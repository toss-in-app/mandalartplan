# 2.0 AI 초안 — 설계 (3단계, 승인 대기)

> 2026-10-19 사용자 결정 "AI 달자" → 2차(2.0.0)의 핵심 기능으로 채택. 기획 메모는 `plans/2.0-ai-draft.md`.
> 이 문서는 설계안이다. 승인 전에는 코드를 만들지 않는다(워크플로 규칙). 아래 "정할 것"이 정해지면 5단계로 간다.

## 정할 것 (사용자)
| # | 항목 | 제안 | 비고 |
|---|---|---|---|
| 1 | 모델 | 품질 비교 뒤 결정. 후보 Claude Haiku 5.5 · Sonnet 5.5 · Opus 5.5 | 한 판 비용(아래 표)이 20배 이상 차이. 목표 20개로 세 모델 결과를 나란히 보고 고른다(비교 비용 수백 원 이하) |
| 2 | 광고 | 첫 초안 1회 무료(기기별), 다시 만들기·빈 칸 채우기·실천 추천은 리워드 광고 | 새 리워드 광고 그룹 1개 필요(지면 승인 최대 24시간) |
| 3 | 매일 저녁 알림 | 2.0 에 같이 넣기 | 제목 7자 이내(예: "실천 체크"), 발송 시각 정하기 |
| 4 | 버전 | 2.0.0 | 서버·새 화면·정책 고지가 들어가는 큰 변경 |
| 5 | 준비물(사용자 직접) | Anthropic 콘솔 계정·API 키·크레딧·워크스페이스 월 사용 한도, Supabase CLI 로그인 | 키는 Claude 가 만지지 않는다. `supabase secrets set` 은 사용자가 실행 |

### 모델별 한 판 비용 (가격표 2026-10-19, 1달러 1,400원, 2단계 생성 기준 입력 약 1.8만·출력 약 3천 토큰)
| 모델 | 입력/출력 (100만 토큰당) | 한 판 | 1만 판 |
|---|---|---|---|
| Claude Haiku 5.5 (`claude-haiku-5-5`) | $0.10 / $0.50 | 약 5원 | 약 4.6만 원 |
| Claude Sonnet 5.5 (`claude-sonnet-5-5`) | $2 / $10 | 약 92원 | 약 92만 원 |
| Claude Opus 5.5 (`claude-opus-5-5`) | $4 / $20 | 약 185원 | 약 185만 원 |

시스템 프롬프트는 캐시(5.5 세대 최소 512토큰)로 반복 입력 비용을 줄인다. 실제 토큰은 구현 뒤 `usage` 로 다시 잰다.

## 사용자 흐름
1. **들어가는 곳**: 빈 판 홈 [AI로 초안 만들기](주) · [예시로 시작하기](보조). 핵심 목표 편집 화면 [빈 칸 AI로 채우기]. 세부 목표 편집 화면 [실천 AI로 추천].
2. **처음 한 번 사전 고지**(정책 2-4): 바텀시트 "이 기능은 생성형 AI(Anthropic Claude)를 써요. 입력한 목표와 판의 글이 초안을 만드는 데 쓰이고 해외(미국)로 전송돼요. 결과는 고쳐 쓰는 초안이에요." [확인] → `settings.ai.noticeAt`. 진입 즉시 띄우지 않고, 버튼을 누른 뒤에만.
3. **목표 입력**(새 화면 `#/draft`): 40자 입력 + 예시 칩(8구단 드래프트 1순위 · 토익 900점 · 올해 10kg 감량). 판에 핵심 목표가 있으면 채워 둔다.
4. **생성**: ① 세부 목표 8개가 먼저 3×3 에 뜬다(1~3초) ② 이어서 실천 64개가 채워진다(3~8초). 로딩은 칸 단위 스켈레톤.
5. **미리보기**: 9×9 + "AI 초안" 배지. [이대로 시작하기] · [다시 만들기](리워드) · [닫기].
6. **적용**: 빈 칸만 채운다(이미 쓴 글은 덮어쓰지 않음). 판에 `aiDraft {at, model}` 를 남기고 홈·전체 보기 제목 아래 "AI 초안" 표시, 공유 이미지에 "AI 초안 포함" 한 줄(정책 2-4 표시 의무).
7. **실패 화면**: 한도 초과 "오늘은 AI 초안을 더 만들 수 없어요. 내일 다시 해 주세요" · 거절 "이 목표로는 초안을 만들 수 없어요. 다른 목표로 해 볼까요" · 자해·자살 표현 "지금 힘든 마음이 있다면 자살예방 상담전화 109 에서 이야기를 들어 줘요"(생성하지 않음) · 네트워크·시간 초과 "잠시 뒤에 다시 해 주세요" + [예시로 시작하기].

## 서버 — Supabase Edge Function `mandalart-draft`
- 런타임: 기존 Supabase 프로젝트(서울)의 Edge Function(Deno). Claude 호출은 공식 TypeScript SDK `npm:@anthropic-ai/sdk`. API 키는 Supabase secrets 의 `ANTHROPIC_API_KEY` 에만 둔다(클라·저장소·로그에 없음).
- 요청 `POST /functions/v1/mandalart-draft` (헤더 `apikey: <publishable key>`)
  - `{ mode: "subs", key, goal, subs: string[8] }` → 빈 세부 목표만 채운 8개
  - `{ mode: "actions", key, goal, subs: string[8], actions: string[8][8], only?: number }` → 빈 실천만 채운 8×8 (`only` 면 그 세부 목표 하나만)
- 응답 `{ ok: true, subs | actions, model, promptVersion }` 또는 `{ ok: false, error: "refused" | "self_harm" | "limited" | "invalid" | "busy" }`
- Claude 호출: `client.messages.parse` + `output_config.format`(zod 스키마, 구조화 출력), `effort: "low"`, 생각은 기본(adaptive), `temperature` 등 샘플링 값은 보내지 않는다(Haiku 5.5 는 기본값 외 400). `max_tokens` 는 subs 2,000 · 세부 목표 하나당 2,000. `actions` 는 세부 목표 8개를 병렬 8회 호출로 나눈다.
- 거절: `stop_reason === "refusal"` 이면 `refused`. 파싱 실패(`parsed_output` null)는 1회만 다시 시도하고 그래도 실패면 `invalid`.
- 입력 검사: 목표 1~40자, 제어문자 제거. 자해·자살 표현 목록에 걸리면 Claude 를 부르지 않고 `self_harm`.
- 출력 검사: 개수 정확히 8·8×8, 칸마다 1~40자(프롬프트는 14자 이내 요청), URL·이메일·전화번호·이모지 없음, 중복 제거. 걸리면 그 칸을 비워 두고 1회 재요청.
- 남용 방지: Postgres 표 `ai_draft_usage(key_hash, day, calls)` + RPC `ai_draft_take(p_key, p_day)`(security definer, 백업 RPC 와 같은 방식). 기기 키당 하루 30회, 전체 하루 3,000회를 넘으면 `limited`. Anthropic 워크스페이스 월 사용 한도가 마지막 방어선. 키는 익명 키 해시(위조 가능)라 1차 방어는 전체 상한이다. 필요해지면 사용자 식별키 인증 코드 교환(SDK 3.6.0+·mTLS)으로 올린다(`plans/2.0-ai-draft.md` 문서 확인 반영 절).
- 저장하지 않는 것: 목표 문구·생성 결과. 남기는 것: 키 해시별 날짜·호출 수, 결과 코드·소요 시간(본문 없음).
- CORS: `https://mandalartplan.apps.tossmini.com`, `https://mandalartplan.private-apps.tossmini.com`(SDK 3.2.0 = 3.1.0 이상 규칙), 개발용 localhost.
- 재시도: 서버는 Claude 실패 시 1회만, 클라는 자동 재시도 없음(정책 2-5 "실패 직후 무제한 재시도 금지").
- 프롬프트 버전: `PROMPT_VERSION` 상수. 모델·프롬프트를 바꾸면 앱 업데이트 출시 노트에 적는다(AI 채팅·상담 요건 "모델·프롬프트 변경 시 사전 검토"를 보수적으로 따름).
- 구현 때 확인할 것: 새 publishable key 와 Edge Function JWT 검증(`--no-verify-jwt` 필요 여부), Edge Function 에서 RPC 를 부르는 키 종류, Deno 에서 `npm:` SDK 와 zod 헬퍼 동작.

## 프롬프트 (요지, 한국어)
- 역할: 만다라트 코치. 핵심 목표를 이루는 데 필요한 서로 겹치지 않는 세부 목표 8개, 세부 목표마다 매일·매주 실천할 수 있는 구체적 행동 8개.
- 형식: 칸에 들어가게 14자 이내 명사형·행동형("아침 스트레칭 10분"), 숫자로 측정 가능하게, 존댓말·느낌표·이모지 없이.
- 이미 쓴 칸은 그대로 두고 빈 칸만 채운다(입력으로 받은 판을 존중).
- 거절: 범죄·약물·도박·폭력·선정·혐오·위험 행동 목표는 만들지 않는다. 의료·투자 판단은 일반 습관 수준으로만.
- 예시 1개(오타니식 "8구단 드래프트 1순위" 같은 실명 없는 운동 목표 예시)를 넣어 형식을 고정한다. 실존 인물 이름은 화면·프롬프트 예시에 쓰지 않는다.

## 계약 변경 (필드 추가만)
- `contract/state.schema.json`: `boards[].aiDraft: { at: number, model: string } | null`, `settings.ai: { noticeAt: number | null, freeUsed: boolean }`
- `contract/ai-draft.api.md`(신규): 위 요청·응답 형식, 오류 코드, 한도
- `contract/events.md`: `ai_notice_agree` · `ai_draft_request {mode}` · `ai_draft_result {mode, result, ms}` · `ai_draft_apply {mode, filled}` · `ai_draft_reward {result}`
- `supabase/schema.sql`: `ai_draft_usage` 표 + `ai_draft_take` RPC
- `static/privacy/`: AI 초안 항목 — 처리 목적, 항목(입력한 목표·판의 글), 국외 이전(Anthropic, PBC·미국·전송 시점·보관하지 않음·Anthropic 보관 정책), 거부 방법(기능을 쓰지 않으면 전송 없음)
- 광고: 콘솔에 리워드 그룹 `AI 초안_리워드광고 (rewarded-ai-draft)` 추가, `client/.env.production` 에 ID

## 테스트
- 단위: 병합(빈 칸만), 출력 검사, 한도·오류 화면, 고지 1회, 라벨·공유 이미지 표시, 광고 흐름(무료 1회 → 리워드).
- 프롬프트 평가 세트(20개): 일상 목표 12 · 애매한 목표 4 · 거절돼야 할 목표 4(범죄·자해 등). 모델 비교와 회귀에 같이 쓴다. 실행마다 비용이 드니 돌리기 전에 사용자 확인.
- 실기기 QR: 생성 시간, 실패·오프라인, 광고, 라벨, 백업 복원 뒤 라벨 유지.

## 순서 (승인 뒤)
3 설계 승인 → 5 구현(서버 함수·RPC → 클라 화면 → 고지·라벨 → 광고) → 6 테스트(평가 세트 포함) → 8 배포(Edge Function·secrets·SQL·처리방침) → 9 콘솔(광고 그룹, 필요 시 앱 정보 문구) → 10 QR → 11 검토 → 12 출시 2.0.0
