시안을 그리며 더한 것(설계와 함께 승인됨):
- 홈 'AI로 초안 만들기'는 빈 판만이 아니라 **세부 목표가 하나도 없을 때** 보인다(핵심 목표만 적은 때 포함). 핵심 목표를 적었으면 목표 입력 화면에 미리 들어가 있다
- 홈 버튼에는 AD 표시를 붙이지 않는다(누를 때 광고가 나오지 않음). AD 표시는 실제로 광고가 나오는 버튼('광고 보고 만들기'·'다시 만들기'·'빈 칸 AI로 채우기'·'실천 AI로 추천')에만
- 버튼 위 안내에 남은 횟수 "오늘 n번 남았어요", 다 쓰면 버튼을 잠그고 "오늘 AI 초안 10번을 다 썼어요. 내일 다시 만들 수 있어요"
- 'AI 초안' 표시는 부제 앞 글자 대신 **제목 위 배지**(미리보기·홈)
- 만드는 중: 진행 막대(실천 n/8)와 아직 안 채운 칸 자리 깜빡임(동작 줄이기면 멈춤), "10초쯤 걸려요. 화면을 나가면 만들던 초안은 사라져요"
- 거절됐을 때 입력칸 아래 빨간 안내 + "방금 본 광고는 오늘 횟수에서 빼지 않았어요"
- 자해·자살 표현 안내 상자에 '109에 전화하기' 버튼

## 수익 구조 (Haiku 5.5, 광고 1회 = AI 1회)
| 작업 | AI 비용(캐시 적용 / 미적용) | 본전 되는 순 eCPM |
|---|---|---|
| 판 전체(세부 목표 8 + 실천 64) | 약 3.1원 / 4.6원 | 약 3,100~4,600원 |
| 세부 목표 빈 칸만 | 약 0.3원 | 약 300원 |
| 실천 8개 추천 | 약 0.3원 | 약 300원 |

- 파트너 몫은 광고 매출의 약 70%(운영비 30%), 수수료 15% 부활 시 약 60%. 생각 토큰이 붙으면 비용이 늘 수 있어 구현 뒤 `usage` 로 실측한다.
- 기존 리워드 지면 2곳의 1~2주 실측 eCPM 으로 마진을 다시 본다. 매주 '광고 수익 − AI 비용' 확인, 마이너스면 상한을 줄인다. 광고 빈도를 원격으로 늘리지 않는다.
- 리워드 광고는 서버 검증이 없다 → 서버 상한(키당 하루 100 호출, 전체 하루 30,000 호출 — 판 전체 1회가 최대 9 호출이라 처음 안의 30·3,000 에서 올림, 2026-10-20)과 Anthropic 월 사용 한도가 우회 방어선.

- 버튼마다 AD 표시 + '광고를 끝까지 보면 …' 안내(노출 정책 UX 원칙 2). 광고를 끝까지 보지 않으면(보상 이벤트 없음) 만들지 않는다.
- 사전 고지 바텀시트는 버튼을 누른 뒤 처음 한 번만(진입 즉시 금지). 다이얼로그 왼쪽 버튼 '닫기'.
- 적용은 빈 칸만. 판에 `aiDraft` 를 남기고 홈·전체 보기 부제 앞에 "AI 초안 ·", 공유 이미지 아래에 "AI 초안 포함"(정책 2-4 표시).
- 실패 안내(토스트·인라인): 한도 "오늘은 AI 초안을 더 만들 수 없어요. 내일 다시 해 주세요" · 거절 "이 목표로는 초안을 만들 수 없어요" · 자해·자살 표현 "지금 마음이 힘들다면 자살예방 상담전화 109 에서 이야기를 들어 줘요"(만들지 않음, 광고도 띄우지 않음) · 광고를 못 불러옴 "지금은 광고를 불러올 수 없어요"(만들지 않음) + [닫기][예시로 시작하기] · 연결 "잠시 뒤에 다시 해 주세요" + [예시로 시작하기]. 광고를 본 뒤 실패하면 광고 보상은 소진되지만 하루 상한에는 넣지 않는다.

## 서버 — Supabase Edge Function `mandalart-draft`
- 위치 `supabase/functions/mandalart-draft/`(`index.ts` 요청 처리 · `prompt.ts` · `validate.ts` · `limits.ts` + Deno 테스트). 기존 서울 리전 프로젝트.
- Claude 호출: 공식 SDK `npm:@anthropic-ai/sdk`, `client.messages.parse` + `output_config: { effort: "low", format: zodOutputFormat(스키마) }`. `model: "claude-haiku-5-5"`. 생각은 기본(adaptive) — 평가 세트로 `low`·`medium` 과 생각 끄기(`{type: "disabled"}`, low/medium/high 에서만 허용)를 비교해 정한다. `temperature`·`top_p`·`top_k` 는 보내지 않는다(Haiku 5.5 는 기본값 외 400). prefill 없음.
- `max_tokens`: 세부 목표 2,000 · 실천 호출당 2,000(생각 포함 여유). 응답은 `type` 으로 블록을 읽는다(앞에 thinking 블록이 올 수 있음).
- 시스템 프롬프트는 `cache_control: { type: "ephemeral" }` 로 캐시(5.5 세대 최소 512토큰). 실천 8회 병렬 호출이 같은 프롬프트를 쓴다.
- 거절: `stop_reason === "refusal"` 이면 `refused`(Haiku 5.5 는 서버 측 fallback 없음 — `fallbacks` 보내지 않음). 모델이 `refused: true` 를 내도 `refused`.
- 실패 재시도: SDK `maxRetries: 1`, 파싱 실패 1회 재요청, 그 뒤 `invalid`. 클라 자동 재시도 없음(정책 2-5).
- 시간: SDK `timeout` 25초. 세부 목표 1~3초, 실천 병렬 3~8초 예상.
- 남용 방지·비용 기록(SQL):
```sql
create table public.ai_draft_usage (key_hash text check (key_hash ~ '^k[0-9a-f]{64}$'), day date, calls int not null default 0, primary key (key_hash, day));
create table public.ai_draft_cost (day date primary key, calls int not null default 0, input_tokens bigint not null default 0, output_tokens bigint not null default 0, cache_read_tokens bigint not null default 0, cache_write_tokens bigint not null default 0);
-- 둘 다 RLS on, 정책 없음, anon·authenticated 권한 회수
-- ai_draft_take(p_key) → boolean: 서울 날짜 기준 전체 30,000 · 키당 100 을 넘으면 false, 아니면 +1 (security definer)
-- ai_draft_cost_add(p_calls, p_in, p_out, p_cache_read, p_cache_write): 오늘 행에 더함
-- 두 함수 실행 권한은 서버 키(service role)만 — anon 에 주지 않는다(직접 불러 상한을 소진시키는 것 방지)
```
- 저장하지 않는 것: 목표 문구·판의 글·생성 결과. 남기는 것: 키 해시별 날짜·호출 수, 날짜별 토큰 합계, 결과 코드 로그(본문 없음).
- CORS 허용: `https://mandalartplan.apps.tossmini.com`, `https://mandalartplan.private-apps.tossmini.com`(SDK 3.1.0 이상 규칙), 개발용 `http://localhost:5180`.
- 키 해시: 클라가 익명 키로 `k` + sha256("ai:" + 익명 키 해시) 를 만들어 보낸다(백업 키와 다른 값). 위조 가능 — 1차 방어는 전체 상한.
- 프롬프트 버전 `PROMPT_VERSION`. 모델·프롬프트 변경은 앱 업데이트와 같이 하고 출시 노트에 적는다.

## 안전
- 입력: 목표 1~40자, 칸 글 0~40자, 제어문자 제거. 자해·자살 표현 목록(예: 죽고 싶, 자살, 자해, 극단적 선택 …)에 걸리면 Claude 를 부르지 않고 `self_harm` — 클라는 광고 전에 같은 목록으로 한 번 더 막는다.
- 프롬프트: 범죄·감시·약물·도박·자해·선정·혐오 거절, 건강·돈은 일반 습관 수준(약·극단 식단·진단·종목 없음), 실존 인물·브랜드 이름 없음, 입력 속 지시문 무시.
- 출력 검사: 정확히 8개, 칸 1~40자(세부 10자·실천 14자 넘으면 기록만), 마침표·느낌표·물음표·따옴표·이모지·URL·이메일·전화번호 금지, 중복 제거, 사용자가 적은 칸은 서버가 원래 글로 되돌린다. 걸린 칸은 비우고 3칸 넘게 비면 1회 재요청.
- AI 채팅·상담 화면이 아니다(대화창 없음). 그래도 위 거절·안전 안내는 그 기준에 맞춘다.

## 테스트
- 단위(클라): 빈 칸만 병합, 고지 1회, 광고 보상 없으면 생성 안 함, 광고를 못 불러오면 생성 안 함, 하루 상한 10회·남은 횟수 표시, 실패 안내, 라벨·공유 이미지 표시.
- 단위(서버, Deno): 입력·출력 검사, 사용자 칸 보존, 거절·자해 경로, 상한 RPC 모의, CORS.
- 평가 세트 20개(`plans/2.0-ai-eval-goals.json`): effort `low`/`medium`·생각 끄기 비교, 형식 통과율·거절 정확도·사람 눈 품질. 한 바퀴 비용 약 100원 이하 — 돌리기 전에 사용자 확인.
- 실기기 QR: 생성 시간, 광고 흐름, 실패·오프라인, 라벨, 백업 복원 뒤 라벨 유지.

## 구현 때 확인할 것 (2026-10-20 확인)
- JWT 검증: publishable key 는 JWT 가 아니라 게이트웨이 JWT 검증을 통과하지 못해요 → `supabase functions deploy mandalart-draft --no-verify-jwt`, 함수 안에서 Origin(토스 미니앱 2개 + 개발 서버)과 publishable key(`SUPABASE_PUBLISHABLE_KEYS`)를 확인(Supabase API Keys 문서).
- 서버 키: Edge Function 에 `SUPABASE_SECRET_KEYS`(JSON, `default`)가 들어와요 → `apikey` 헤더로 DB 함수 호출. 없으면 예전 `SUPABASE_SERVICE_ROLE_KEY`(Supabase Functions Secrets 문서). `ANTHROPIC_API_KEY` 는 `supabase secrets set`(이름이 `SUPABASE_` 로 시작하면 거부).
- SDK: `npm:@anthropic-ai/sdk@0.131.0` 의 `messages.create` + `output_config: { effort, format: { type: 'json_schema', schema } }` — zod 헬퍼 없이 JSON 스키마. 배열 길이·글자 수 제약은 구조화 출력이 받지 않아(Claude API 문서 'JSON Schema Limitations') 서버 검사(`validate.ts`)로만.
