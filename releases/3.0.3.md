## 바뀐 것
- **왜**: 2.0.0(2026-10-20)부터 AI 초안 리워드가 '두 번째 판' 지면(`ait.v2.live.4f0aaab3a62749d1`, 콘솔 보상 이름 '기회' 1)을 같이 썼다 — 전면·리워드 지면 신규 생성 오류(앱인토스 공지 54047) 동안 전용 지면을 만들 수 없어서. 2026-10-28 12시 복구(공지 54525) 뒤 10-29 17:55 전용 지면 `rewarded-ai-draft`(`ait.v2.live.d29d6a0146a9451a`, 보상 'AI 초안' 1)를 만들었다.
- **바뀐 곳**: `client/.env.production` 의 `VITE_AD_GROUP_REWARDED_AI_DRAFT` 한 줄. `App.tsx` 는 두 설정의 ID 가 같을 때만 '두 번째 판' 훅 하나로 묶으므로(`aiSharesExtraBoard`) 코드는 그대로다. 출시 빌드에서는 AI 화면(초안 화면·홈 'AI로 빈 칸 채우기'·세부 목표 화면 '빈 실천 AI로 채우기')이 AI 지면만, 설정 '두 번째 만다라트 판'이 두 번째 판 지면만 미리 불러온다. 두 훅이 한 화면에서 함께 켜지는 일은 없다(설정과 AI 화면은 따로).
- **그대로**: 광고 스위치 `VITE_FULL_SCREEN_ADS=ios`(전면·리워드는 iOS 만, 안드로이드는 광고 없이 바로), 화면·문구·AD 표시·AI 하루 20회, 배너, 나머지 지면 4개.
- **주석**: `App.tsx`(광고 스위치 설명이 3.0.1 'off' 로 남아 있던 것, 공유 묶음 설명), `ads/config.ts`, `scripts/check-release-bundle.mjs`.
- **앱 버전 표시**: 설정 화면 '앱 버전 3.0.3'.
- **콘솔(3.0.3 라이브 뒤)**: '두 번째 판' 지면의 표시 이름에서 '·AI 초안(임시)'를 빼고 보상 이름을 '두 번째 만다라트 판' 1 로 되돌린다(`iaa_placement_group_update`). 그 전에는 라이브 3.0.2 의 AI 초안도 이 지면을 써서 '기회'가 맞다.

## 확인
- 새 테스트 `client/src/App.adGroups.test.tsx` 3개: ID 가 다르면(출시 빌드) 홈 'AI로 빈 칸 채우기'는 AI 지면만 미리 불러오고 그 훅으로 광고를 보고, 설정 두 번째 판은 두 번째 판 지면만 · ID 가 같으면(테스트 ID, 2.0.0~3.0.2) AI 도 두 번째 판 훅 하나로. 연결을 일부러 틀리게 바꾸면(`aiReward` 를 늘 AI 훅으로 / 늘 두 번째 판 훅으로) 각각 한 개씩 실패하는 것을 확인했다.
- `npm run check` 통과(계약 검증·타입·린트·테스트 308개(42파일)·출시 번들 검사: 테스트 광고 ID 0개, 라이브 광고 그룹 5개·설정 5곳·ait 빌드) — 2026-10-29.
- 실기기(라이브 번들, 지면 승인 뒤): **아이폰** — AI 초안·빈 칸 채우기 광고가 뜨고 끝까지 보면 AI 가 채우는지(새 지면), 설정 두 번째 판 '광고 보기'도 뜨는지(기존 지면). 라이브 광고 ID 번들이라 광고는 누르지 않고 뜨는지만 본다(반복 시청 금지). **안드로이드** — 3.0.2 처럼 광고 없이 바로. 출시 빌드에서 AI 와 두 번째 판이 서로 다른 지면을 쓰는 건 처음이라(2.0.0 부터 같은 지면) 이 확인이 그 경로의 첫 실기기 확인이다 — 테스트 번들은 리워드 테스트 ID 가 하나라 묶인 쪽으로만 돈다.
- 지면 상태: 생성 응답은 ENABLED + groupId. 목록 반영(REGISTERING, 최대 2시간) 뒤 같은 ID 인지 다시 보고, 실제 송출은 지면 승인(최대 24시간) 뒤라 실기기 확인·검토 요청은 2026-10-30 부터.
