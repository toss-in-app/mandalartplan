## 바뀐 것
### 1. 안드로이드도 전면·리워드 광고를 다시 켬
- **스위치** `client/.env` `VITE_FULL_SCREEN_ADS`: `ios` → **`on`**. 코드는 그대로라 안드로이드도 3.0.0·iOS 와 같은 흐름이다 — 홈 '기록 보기' 전면(하루 1회, AD 표시 + '기록 보기를 누르면 광고가 한 번 나와요' 안내), 리워드 3곳(AI 초안·빈 칸 채우기 / 공유 '고화질로 저장' / 설정 '두 번째 만다라트 판' — AD 표시·'광고 보고' 문구·'광고를 한 번 보면' 안내), 분석 `ad_interstitial`·`reward_unlock`·`ai_draft_reward`.
- **위험**: 3.0.1 에서 끈 이유(안드로이드 토스앱이 광고 이벤트를 늦게/안 보내, 2026-10-22 실기기 영상에서 라이브 리워드 광고를 50초 다 봤는데 앱은 '못 불러왔다')가 고쳐졌다는 공지는 아직 없다. 2026-10-29 확인: 개발 공지 최신은 4951(10/09), 4529(에러 콜백 미호출)는 완료 공지 없음, 비슷한 보고 5057(10/22)에 10/28 토스 답은 "애드몹 자체 로딩이 오래 걸릴 수 있으니 타임아웃을 더 늘리거나 없애는 것도 고려" — 버그 수정 안내가 아니다.
- 그래서 **안드로이드 실기기 확인을 출시 조건**으로 둔다(아래 '확인'). 안 되면 `ios` 로 되돌리거나, 보관해 둔 광고 기다림 수정(`47c019a`, 원격 브랜치 `claude/edit-swap-records-padding`: 누른 뒤 10초 안에 준비된 광고만·버튼 로딩 표시·가려짐/터치로 판정·닫힐 때 몰려온 보상 인정·늦은 보상 120초)을 넣는다. 이번에 넣지 않은 이유: 실기기 확인·심사를 거치지 않은 큰 변경이고(약 650줄, 3.0.1 첫 판은 반려) iOS 흐름까지 바뀐다.
- 콘솔 상세 설명은 그대로('핵심 목표만 적고 생성형 AI(Anthropic Claude)를 통해 …') — 광고 언급이 없어 켜도 틀리지 않는다. 바꾸면 앱 정보 검토가 따로 걸린다.

### 2. AI 초안 리워드를 전용 지면으로
- **왜**: 2.0.0(2026-10-20)부터 AI 초안 리워드가 '두 번째 판' 지면(`ait.v2.live.4f0aaab3a62749d1`, 콘솔 보상 이름 '기회' 1)을 같이 썼다 — 전면·리워드 지면 신규 생성 오류(앱인토스 공지 54047) 동안 전용 지면을 만들 수 없어서. 2026-10-28 12시 복구(공지 54525) 뒤 10-29 17:55 전용 지면 `rewarded-ai-draft`(`ait.v2.live.d29d6a0146a9451a`, 보상 'AI 초안' 1)를 만들었다.
- **바뀐 곳**: `client/.env.production` 의 `VITE_AD_GROUP_REWARDED_AI_DRAFT` 한 줄. `App.tsx` 는 두 설정의 ID 가 같을 때만 '두 번째 판' 훅 하나로 묶으므로(`aiSharesExtraBoard`) 코드는 그대로다. 출시 빌드에서는 AI 화면(초안 화면·홈 'AI로 빈 칸 채우기'·세부 목표 화면 '빈 실천 AI로 채우기')이 AI 지면만, 설정 '두 번째 만다라트 판'이 두 번째 판 지면만 미리 불러온다. 두 훅이 한 화면에서 함께 켜지는 일은 없다(설정과 AI 화면은 따로).
- **콘솔(3.0.3 라이브 뒤)**: '두 번째 판' 지면의 표시 이름에서 '·AI 초안(임시)'를 빼고 보상 이름을 '두 번째 만다라트 판' 1 로 되돌린다(`iaa_placement_group_update`). 그 전에는 라이브 3.0.2 의 AI 초안도 이 지면을 써서 '기회'가 맞다.

### 3. Microsoft Clarity(화면 녹화·히트맵) — 사용자 2026-10-29
- **켜는 곳**: 공식 npm `@microsoft/clarity` 1.0.2(MIT, 의존성 없음 — `https://www.clarity.ms/tag/<id>` 스크립트를 넣는 작은 로더). `client/src/lib/clarity.ts` `startClarity` 를 `main.tsx` 가 렌더 전에 부름: 출시 빌드(MODE=production)에서 `.env.production` `VITE_CLARITY_PROJECT_ID=z58r4u0qo8` 가 있을 때만 `Clarity.init` + 태그 `app_version`. 개발 서버·vitest·`build:test-ads` 는 녹화 안 함. 실패해도 앱은 그대로.
- **가림**: `client/index.html` `<body data-clarity-mask="True">` — 토스 바텀시트·토스트처럼 #root 밖에 그려지는 것까지 글자를 모두 가리고, 가린 내용은 보내지 않는다(콘솔 마스킹 Strict 와 별개로 코드에서 보장). 입력칸은 원래 늘 가림. `identify` 를 쓰지 않아 토스 식별값은 보내지 않는다. 캔버스(공유 카드)는 녹화에 안 담긴다.
- **CSS 를 페이지 안으로**: 미니앱 주소는 토스 앱 밖에서 열리지 않아(직접 접속 HTTP 400) 클라리티가 재생할 때 CSS 파일을 다시 받지 못한다 → `vite.config.ts` `inlineCss()` 가 빌드 때 CSS(17KB)를 `index.html` 안 `<style>` 로 넣고 CSS 파일을 뺀다. TDS(emotion) 스타일은 실행 중에 넣는 것이라 녹화에 담기는지 첫 녹화로 본다.
- **출시 검사**: `scripts/check-release-bundle.mjs` 가 Clarity ID 가 번들에 있는지, body 가림이 있는지, CSS `<link>` 가 남지 않았는지도 본다.
- **아직(검토 전)**: 개인정보처리방침 — Microsoft(미국) 국외 이전(화면 이동·터치·스크롤 기록(글자는 가림)·기기 정보·쿠키 식별값, 녹화 30일·일부 표본 최대 9개월, Azure), 거부 방법. 클라리티 약관상 사용자에게 알려야 한다. 출시 노트 초안에도 한 줄.
